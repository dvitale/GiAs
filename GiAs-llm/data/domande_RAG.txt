  La tabella intent_examples e' la single source of truth per tutti gli esempi
  di classificazione, comprese le domande RAG curate manualmente.

  Il campo risposta nella tabella e' opzionale e puramente documentale — non viene usato dal sistema
  per rispondere. Serve a te per annotare la risposta attesa.

  La risposta vera viene dal RAG, cioe' dai PDF gia' indicizzati in Qdrant (collection documents, non
  intent_examples). Quando una domanda viene classificata come info_procedure, il sistema cerca nei
  chunk dei PDF indicizzati e genera la risposta da li'.

  In sintesi il flusso e':

  Domanda utente
    -> Classificatore (few-shot da intent_examples) -> intent = info_procedure
      -> RAG cerca nei PDF indicizzati -> genera risposta

  Se vuoi inserire domande su argomenti non coperti dai PDF attuali, devi prima indicizzare i documenti
  pertinenti e poi aggiungere le domande nella tabella.

● Cosa dovrai fare tu

  1. Verificare la copertura PDF

  Prima di inserire una domanda, assicurati che la risposta sia gia' nei PDF indicizzati nel RAG. I
  documenti attualmente indicizzati sono quelli nella pipeline RAG (es. ManualeGisa.pdf,
  help_matrix_rev1.5.pdf, ecc.).

  Se la risposta non e' coperta da nessun PDF -> prima indicizza il documento, poi aggiungi la domanda.

  2. Inserire le domande nella tabella

  INSERT INTO intent_examples (text, intent, source) VALUES
    ('Cos''e il borsellino in Matrix?', 'info_procedure', 'help_matrix_rev1.5.pdf');

  Campi obbligatori: text e intent. Tutto il resto ha default sensati (example_type = 'few_shot',
  active = TRUE).

  Campi opzionali utili:
  - risposta — per tua documentazione (il sistema non la usa)
  - source — per ricordarti quale PDF contiene la risposta
  - notes — note libere
  - example_type — default 'few_shot', oppure 'disambiguation', 'variation', 'help'
  - confused_with — intent confondibile (per type 'disambiguation')

  3. Ricostruire l'indice Qdrant

  Dall'interfaccia admin: POST /api/admin/domande-rag/reindex

  Oppure da terminale:
  cd GiAs-llm && python tools/indexing/build_intent_examples_index.py

  4. Riavviare il backend

  scripts/server.sh restart

  Necessario perche' il Router carica il prompt di classificazione all'avvio.

  In sintesi

  Verifichi che il PDF sia indicizzato
         |
  INSERT nella tabella intent_examples
         |
  POST /api/admin/domande-rag/reindex  (o python tools/indexing/build_intent_examples_index.py)
         |
  scripts/server.sh restart
         |
  Pronto — testa la domanda

  Puoi accumulare molte domande e lanciare il reindex una sola volta alla fine.

  INSERT INTO intent_examples (text, intent, example_type, confused_with) VALUES

  Formato CSV

  File con header:
  text,risposta,intent,source
  "Cos'e il borsellino?","Il borsellino e' il contenitore...","info_procedure","help_matrix_rev1.5.pdf"
  "Cosa significa preaccettazione?","La preaccettazione e'...","info_procedure","help_matrix_rev1.5.pdf"

  Comando di caricamento

  PGPASSWORD=xxx psql -h localhost -U gisa_owner -d gias_db -c "\copy
  intent_examples(text, risposta, intent, source) FROM 'data/domande.csv' WITH (FORMAT csv, HEADER
   true, ENCODING 'UTF-8')"

  I campi omessi (example_type, active, ecc.) prendono i default della tabella.

  Nota sulla idempotenza

  Il \copy non gestisce ON CONFLICT — se rilanci il caricamento con le stesse domande otterrai un
  errore per il constraint UNIQUE (intent, text, example_type). Due opzioni:

  1. TRUNCATE prima del reload (ATTENZIONE: cancella anche gli esempi di sistema)
  2. Passa da tabella staging: carica in una temp table, poi INSERT ... ON CONFLICT DO NOTHING

  Per un workflow semplice (prepari il CSV, carichi una volta, lanci il reindex) il \copy diretto va
  benissimo.
